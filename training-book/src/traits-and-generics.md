Скалярное произведение двух векторов — это одно число, равное сумме произведений их компонент. Например, `[1, 2] * [3, 4] = 1 * 3 + 2 * 4 = 11`. ### 2.4.1.C Делаем `Vec2D` обобщённым
Сейчас компоненты `x` и `y` нашего `Vec2D` могут быть только 32-битными целыми. А что, если нужны другие числовые типы, например числа с плавающей точкой? Сделаем `Vec2D` обобщённым по типу `T`, изменив определение `Vec2D` так, чтобы `x` и `y` имели обобщённый тип.

Также нужно обновить реализации сложения и скалярного произведения, чтобы они работали с обобщённым типом `T`. Вместо того чтобы реализовывать `add` и `mul` отдельно для каждого числового типа, можно сделать реализации обобщёнными: реализовать их для любого типа `T`, который можно складывать и/или умножать (то есть для любого `T`, реализующего трейты `Add` и/или `Mul`). Тогда достаточно поменять только начало блока `impl`, без изменения самих функций!

<details>
    <summary><b>Подсказка 1 (обобщённые реализации с ограничениями трейтов)</b></summary>
    Обобщённый тип можно добавить в блок `impl`, написав `impl&lt;T&gt;`. Тип можно ограничить трейтом, написав, например, `impl&lt;T: Display&gt;`, что означает, что тип `T` должен реализовывать `Display` (то же самое можно записать как `impl&lt;T&gt; ... where T: Display`). Несколько ограничений можно перечислить через `+`, например `impl&lt;T: Clone + Display&gt;`.
</details>

<details>
    <summary><b>Подсказка 2 (трейты `Add` и `Mul`)</b></summary>
    У трейтов `Add` и `Mul` есть обобщённый associated-тип `Output`. Именно поэтому мы смогли реализовать скалярное произведение как трейт `Mul` для `Vec2D`, задав в качестве результата число. В обобщённой реализации мы хотим, чтобы тип `T` можно было складывать и/или умножать. Для этого добавляем к `T` ограничения `Add` и/или `Mul`, но также нужно указать, какой результат ожидаем от сложения или умножения двух значений `T`, например так: `T: Add&lt;Output = T&gt;`.
</details>

## Упражнение 2.4.2: Вектор с локальным хранилищем (`LocalStorageVec`)

Это бонусное упражнение! Мы создадим тип `LocalStorageVec`, обобщённый список элементов, который хранится либо на стеке, либо в куче, в зависимости от размера. Если элементы достаточно малы, чтобы поместиться на стеке, буфер `LocalStorageVec` реализован массивом. `LocalStorageVec` обобщён не только по типу (`T`) элементов списка, но и по размеру (`N`) массива на стеке, используя относительно новую возможность языка, [константные обобщения (const generics)](https://doc.rust-lang.org/reference/items/generics.html#const-generics). ### 2.4.2.F `Index` ⭐⭐
Чтобы пользователи `LocalStorageVec` могли читать элементы и срезы из его буфера, можно реализовать трейт [`Index`](https://doc.rust-lang.org/std/ops/trait.Index.html). Этот трейт обобщён по типу индекса. Чтобы сделать `LocalStorageVec` универсальным, реализуйте:

- `Index<usize>` — позволяет получить один элемент через `vec[1]`;
- `Index<RangeTo<usize>>` — позволяет получить первые `n` элементов (не включая элемент `n`) через `vec[..n]`;
- `Index<RangeFrom<usize>>` — позволяет получить элементы с позиции `n` до конца через `vec[n..]`;
- `Index<Range<usize>>` — позволяет получить элементы между `n` и `m` (не включая элемент `m`) через `vec[n..m]`.

Каждую из этих реализаций можно выразить через реализацию `as_ref`, поскольку срезы `[T]` поддерживают индексирование всеми перечисленными типами. То есть `[T]` тоже реализует `Index` для этих типов. Раскомментируйте тестовый случай `it_indexes` и запустите `cargo test`, чтобы проверить реализацию.

### 2.4.2.J `Deref` и `DerefMut` ⭐⭐⭐⭐
Следующие трейты, которые сделают `LocalStorageVec` гибче, — это [`Deref`](https://doc.rust-lang.org/std/ops/trait.Deref.html) и [`DerefMut`](https://doc.rust-lang.org/std/ops/trait.DerefMut.html). Они используют возможность Rust «deref coercion», которая позволяет обращаться с типом так, будто это тот тип, на который он похож.
Благодаря этому мы сможем вызывать на `LocalStorageVec` [любой метод, определённый для `[T]`](https://doc.rust-lang.org/std/primitive.slice.html).
Прежде чем продолжить, прочитайте раздел [«Treating a Type Like a Reference by Implementing the Deref Trait»](https://doc.rust-lang.org/book/ch15-02-deref.html#treating-a-type-like-a-reference-by-implementing-the-deref-trait) из *The Rust Programming Language* (TRPL) — раздел о том, как относиться к типу как к ссылке, реализуя трейт `Deref`.
**Не путайте deref coercion с наследованием! Использовать `Deref` и `DerefMut` для имитации наследования в Rust не принято.**

Ниже приведена реализация `Deref` и `DerefMut` через реализации `AsRef` и `AsMut`. Обратите внимание на то, как именно вызываются `as_ref` и `as_mut`.

```rust
impl<T, const N: usize> Deref for LocalStorageVec<T, N> {
    type Target = [T];

    fn deref(&self) -> &Self::Target {
        <Self as AsRef<[T]>>::as_ref(self)
    }
}

impl<T, const N: usize> DerefMut for LocalStorageVec<T, N> {
    fn deref_mut(&mut self) -> &mut Self::Target {
        <Self as AsMut<[T]>>::as_mut(self)
    }
}
```
